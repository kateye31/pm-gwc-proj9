        📘What is encapsulation?2-minute read · the Alchemy Lab's idea

        Encapsulation means hiding an object's data inside it, so the only way in is through its public methods (like getters and setters).

        🥤 Think of a vending machine. The snacks (the data) are locked behind glass. You can't reach in and grab one. You use the buttons and the coin slot (the public methods), and the machine decides the rules.

        🧱 3 steps to encapsulate a class

        1. Make the fields private. That locks the data, so other classes can't change it directly.
        2. Add public getters. Like window-shopping: other classes can see the data.
        3. Add public setters (if you need them). Like the coin slot: other classes can change the data, but only by your rules.

        💻 Without vs. with encapsulation

        ❌ Without it, anyone can put a bad value straight in:

        class BankAccount {
    public double balance;   // anyone can change this!
}

BankAccount account = new BankAccount();
account.balance = -5000;     // 🛑 a negative balance is allowed

        ✅ With it, the data is hidden and the setter checks the rule first:

        class BankAccount {
    private double balance;                  // 1. hide the data

    public double getBalance() {             // 2. getter: let people look
        return balance;
    }

    public void setBalance(double amount) {  // 3. setter: check the rule first
        if (amount >= 0) {
            this.balance = amount;
        } else {
            System.out.println("Error: Balance cannot be negative.");
        }
    }
}

BankAccount account = new BankAccount();
account.balance = -5000;     // ❌ won't even compile now
account.setBalance(-5000);   // ⚠️ prints the error
account.setBalance(150);     // ✅ works

        🏰 In our game: in Lab step 4, the word "work" lives in a private field. The warlock can't grab it. He has to ask the getter.
